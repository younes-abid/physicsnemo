# Section 1: Diffusion Models — The General Idea

## The Core Concept (Two Processes)

Every diffusion model has two processes:

```
FORWARD PROCESS (destroying data — NOT learned):
  Clean image → gradually add noise → pure noise

REVERSE PROCESS (generating data — LEARNED):
  Pure noise → gradually remove noise → clean image
```

Training teaches the reverse process. Generation uses it.

# Section 2: Discrete Diffusion (DDPM — The Original)

**Paper:** Ho et al., 2020 — "Denoising Diffusion Probabilistic Models"

### 2.1 The Forward Process (Adding Noise)

We define T discrete timesteps (typically T = 1000). At each step, we add a
small amount of Gaussian noise controlled by a **variance schedule** β₁, β₂, ..., βT:

```
Forward step (one step at a time):
  x_t = √(1 - βₜ) × x_{t-1} + √(βₜ) × ε    where ε ~ N(0, I)
```

But we **never actually do this step-by-step during training**. There's a
closed-form formula to jump directly from the clean image x₀ to ANY step t:

```
                    ┌─────────────────────────────────────────────────────┐
                    │                                                     │
                    │   x_t = √(ᾱₜ) × x₀  +  √(1 - ᾱₜ) × ε            │
                    │                                                     │
                    │   where:                                            │
                    │     αₜ = 1 - βₜ                                    │
                    │     ᾱₜ = α₁ × α₂ × ... × αₜ  (cumulative product) │
                    │     ε ~ N(0, I)  (fresh random noise)              │
                    │                                                     │
                    └─────────────────────────────────────────────────────┘
```

**Key insight:** We can go from x₀ to x_t in ONE computation. No iteration needed.

The variance schedule β₁...βT is typically **linear**:
```
β₁ = 0.0001  (almost no noise at step 1)
β₂ = 0.0001 + δ
...
βT = 0.02    (moderate noise at step T=1000)

But because ᾱₜ is a CUMULATIVE product, by step T=1000:
  ᾱ₁₀₀₀ ≈ 0.0    → x_T ≈ 0 × x₀ + 1 × ε = pure noise
```

### 2.2 Training (Your Understanding — Corrected)

Here's where your understanding had a **critical error**. Let me fix it:

```
YOUR UNDERSTANDING (WRONG):
  "We train the model to predict step i-1 (move one step back)"

ACTUAL (DDPM):
  "We train the model to predict THE NOISE ε that was added"
  
  The model does NOT predict x_{t-1}. It predicts ε.
```

Here's the actual DDPM training procedure:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        DDPM TRAINING LOOP                               │
│                                                                          │
│  repeat:                                                                 │
│    1. Sample a clean image:    x₀ ~ training data                       │
│    2. Sample a random step:    t ~ Uniform{1, 2, ..., T}                │
│    3. Sample random noise:     ε ~ N(0, I)                              │
│    4. Create noisy image:      x_t = √(ᾱₜ) × x₀ + √(1-ᾱₜ) × ε       │
│    5. Predict the noise:       ε̂ = model(x_t, t)                       │
│    6. Compute loss:            L = ‖ε - ε̂‖²                            │
│    7. Update model weights via gradient descent                          │
│                                                                          │
│  The model input is:  (noisy image x_t,  timestep t)                   │
│  The model output is: predicted noise ε̂                                │
│  The target is:       the actual noise ε that was sampled in step 3     │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**You were right that:**
- ✅ We take a clean image
- ✅ We pick a random step t
- ✅ We add noise using a formula
- ✅ Training is always one step (not iterative)

**You were wrong that:**
- ❌ "We train it to move to step i-1" — No! We train it to predict the noise ε
- ❌ The model doesn't know about "step i-1" during training. It just learns
  to identify what noise looks like at each noise level.

Why predict noise instead of x_{t-1}? Because predicting noise is more stable
and gives better gradients. But mathematically they're equivalent — if you know
ε, you can compute x_{t-1}:

```
x_{t-1} = (1/√αₜ) × (x_t - (βₜ/√(1-ᾱₜ)) × ε̂) + √(βₜ) × z

where z ~ N(0, I) is fresh noise (for stochastic sampling)
      or z = 0 (for deterministic sampling)
```

1. **During training**, the model learns to predict **the total noise ε** that was added to jump from x₀ all the way to x_t (not step-by-step noise, but the **one-shot** noise from the closed-form formula).
2. **During inference**, we have:
    - x_t (the current noisy image)
    - ε̂ (the model's prediction of that total noise)
    - The known schedule values (αₜ, ᾱₜ, βₜ)
3. Then "some advanced math" (rearranging the forward formula) gives us:

x_{t-1} = (1/√αₜ) × (x_t - (βₜ/√(1-ᾱₜ)) × ε̂) + √(βₜ) × z

That's it. You've got it.

## **What each parameter means in that equation**

| Symbol | What it is | Meaning |
| --- | --- | --- |
| **x_t** | Current noisy image | What we have right now at step t |
| **x_{t-1}** | Less noisy image | What we want to compute (one step cleaner) |
| **ε̂** | Model output | The model's prediction of the total noise that was added to get from x₀ to x_t |
| **αₜ** | `1 - βₜ` | How much **signal is preserved** at step t. Close to 1 = almost all signal kept. |
| **ᾱₜ** | `α₁ × α₂ × ... × αₜ` | **Cumulative** signal preservation from step 0 to t. Close to 0 at high t = almost no signal left. |
| **βₜ** | Variance schedule value | How much **noise was added** at step t specifically. A small number (e.g. 0.0001 to 0.02). This is a **predefined constant** — part of the noise schedule chosen before training. |
| **z** | Fresh random noise | `z ~ N(0, I)` for stochastic sampling, or `z = 0` for deterministic. This is what gives you **different outputs** each time you run generation. |
| **√(βₜ)** | Scale of fresh noise | Controls how much randomness is injected at each step. Small because βₜ is small. |

## **Reading the equation intuitively**

x_{t-1} = (1/√αₜ) × (x_t - (βₜ/√(1-ᾱₜ)) × ε̂)  +  √(βₜ) × z

─────────────────────────────────────────     ──────────

DENOISING PART                       NOISE INJECTION

"Remove the predicted noise from x_t,        "Add a tiny bit of

scaled appropriately for this step"           fresh randomness"

The **denoising part** says: take x_t, subtract out a fraction of the predicted noise (scaled by the schedule), and rescale. The **noise injection** part adds a small amount of fresh noise to keep the stochastic process well-behaved (without it, errors accumulate).

## **So what is βₜ concretely?**

βₜ is just a **predefined number from a list** — chosen before training even starts. For the standard linear schedule:

β₁   = 0.0001   (tiny noise at step 1)

β₂   = 0.0001 + δ

β₃   = 0.0001 + 2δ

...

β₁₀₀₀ = 0.02    (moderate noise at step 1000)

where δ = (0.02 - 0.0001) / 999 ≈ 0.00002

It's **not learned**. It's a hyperparameter. Think of it as: "at step t, inject this much noise." The whole list [β₁, β₂, ..., βT] is the **noise schedule**.


### 2.3 Inference/Generation (Your Understanding — Corrected)

Your understanding of inference was **almost right** but missed key details:

```
YOUR UNDERSTANDING:                    ACTUAL:

1. Start with noisy image             1. Start with PURE NOISE x_T ~ N(0,I)
2. Model predicts noise               2. ✅ Model predicts noise ε̂ = model(x_t, t)
3. Remove noise from image            3. ✅ Compute x_{t-1} using the formula
4. Add small extra noise              4. ✅ Add fresh noise z (stochastic sampling)
5. Repeat                             5. ✅ Repeat T times (t = T, T-1, ..., 1)
```

**You were almost right!** The main correction: we start from **pure noise**
(not a "noisy image" — there's no input image at all during generation).

The full DDPM inference loop:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                      DDPM INFERENCE (Generation)                         │
│                                                                          │
│  1. Sample pure noise: x_T ~ N(0, I)    ← start from complete noise    │
│                                                                          │
│  2. For t = T, T-1, T-2, ..., 1:                                       │
│       a. Predict noise:  ε̂ = model(x_t, t)                             │
│       b. Compute:        x_{t-1} = (1/√αₜ)(x_t - βₜ/√(1-ᾱₜ) × ε̂)    │
│                                    + σₜ × z                              │
│          where z ~ N(0,I) if t > 1, else z = 0                          │
│          and σₜ = √(βₜ)  (one common choice)                           │
│                                                                          │
│  3. Return x₀  ← the final denoised image                              │
│                                                                          │
│  Total model calls: T (typically 1000!)                                  │
│  This is why DDPM is SLOW.                                              │
└──────────────────────────────────────────────────────────────────────────┘
```

**About "N is a parameter we choose as input":**

In the original DDPM, N = T = 1000 (the same as training). You **cannot** choose
a different N — you must go through all 1000 steps. This is a major limitation.

Later methods (DDIM, EDM) **did** make this possible — you CAN choose fewer
steps. More on this below.

### 2.4 Where Does σ Appear in Discrete DDPM?

In the original DDPM paper, they don't use σ explicitly. Instead they use:
- βₜ (variance schedule)
- αₜ = 1 - βₜ
- ᾱₜ = cumulative product of αₜ

But you **can** convert to σ notation:

```
σₜ = √((1 - ᾱₜ) / ᾱₜ)

This is the signal-to-noise ratio: when ᾱₜ is large (low noise), σₜ is small.
When ᾱₜ is near 0 (high noise), σₜ is huge.
```

So σ and (β, α, ᾱ) are just different ways of expressing the same thing —
the noise level at each step.

# Section 3: Continuous Diffusion (Score-Based / SDE)

**Paper:** Song et al., 2021 — "Score-Based Generative Modeling through SDEs"

### 3.1 The Key Idea: Replace Discrete Steps with a Continuous Process

Instead of T=1000 discrete steps, imagine the noise being added **continuously**
over a time variable t ∈ [0, 1]:

```
DISCRETE (DDPM):                    CONTINUOUS (SDE):
  t ∈ {1, 2, ..., 1000}             t ∈ [0, 1]  (any real number)
  x₁, x₂, ..., x₁₀₀₀              x(t) for any t
  βₜ is a sequence                   β(t) is a function
  ᾱₜ is a sequence                   noise level σ(t) is a function
```

The forward process is described by a **Stochastic Differential Equation (SDE)**:

```
dx = f(x, t) dt + g(t) dw

where:
  f(x, t) = drift term (how the signal decays)
  g(t)    = diffusion coefficient (how fast noise grows)
  dw      = infinitesimal Wiener process (random noise)
```

**You don't need to understand SDEs to use diffusion models.** The key insight
is simply: continuous time means we can evaluate the noise level at **any** point,
not just at integer steps.

### 3.2 Why Continuous Is Better

```
DISCRETE:                           CONTINUOUS:
  Must use exactly T steps           Can use ANY number of steps
  Steps are fixed at training        Steps can change at inference
  T=1000 → 1000 model calls         Can use 18, 50, or 100 steps
  Noise levels are predetermined     Noise levels can be optimized
```

The continuous formulation enables **flexible sampling** — you choose how many
steps to use at generation time, trading quality for speed.

### 3.3 Training in Continuous Diffusion

Almost identical to DDPM, but with continuous σ instead of discrete t:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                  CONTINUOUS DIFFUSION TRAINING                           │
│                                                                          │
│  repeat:                                                                 │
│    1. Sample a clean image:     x₀ ~ training data                      │
│    2. Sample a noise level:     σ ~ p(σ)    ← continuous distribution!  │
│    3. Sample random noise:      ε ~ N(0, I)                             │
│    4. Create noisy image:       x_noisy = x₀ + σ × ε                   │
│    5. Model predicts denoised:  x̂₀ = model(x_noisy, σ)                │
│    6. Compute loss:             L = w(σ) × ‖x₀ - x̂₀‖²                 │
│    7. Update model weights                                               │
│                                                                          │
│  Note: the model predicts x₀ directly (not ε), but with                │
│  preconditioning it's mathematically equivalent.                         │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**Key difference from DDPM:** Instead of sampling t from {1,...,1000}, we sample
σ from a **continuous distribution** p(σ). This is much more flexible.

### 3.4 Two Flavors: VP and VE

The continuous framework has two main variants:

**Variance Preserving (VP):**
```
x_noisy = √(ᾱ(t)) × x₀ + √(1 - ᾱ(t)) × ε

Signal is SCALED DOWN as noise increases → total variance stays ≈ 1
The original DDPM is the discrete version of VP.
```

**Variance Exploding (VE):**
```
x_noisy = x₀ + σ(t) × ε

Signal is NOT scaled → total variance grows ("explodes") with noise
Simpler formula, but the variance of x_noisy increases.
```

In the codebase, you can see both:
- `VPLoss` / `VPPrecond` — variance preserving
- `VELoss` / `VEPrecond` — variance exploding

# Section 4: EDM — What It Is, What It Does, Why CorrDiff Uses It

**Paper:** Karras et al., 2022 — "Elucidating the Design Space of
Diffusion-Based Generative Models"

**EDM** stands for **"Elucidating the Design Space of Diffusion-Based
Generative Models"** — it's the title of the paper. It's not a new model
architecture; it's a **unified framework** that:

1. Shows that DDPM, Score-SDE (VP), Score-SDE (VE), and others are all
   doing the same thing with different notation
2. Identifies which design choices actually matter
3. Proposes the best combination of those choices

### 4.1 What EDM Does (The Three Big Contributions)

**Contribution 1: Unified Framework**

EDM showed that all previous diffusion models can be written as:

```
D(x; σ) = c_skip(σ) × x + c_out(σ) × F_θ(c_in(σ) × x; c_noise(σ))

where:
  x       = noisy input
  σ       = noise level
  F_θ     = the raw neural network (UNet)
  c_skip  = skip connection weight
  c_out   = output scaling
  c_in    = input scaling
  c_noise = noise label for the network
  D(x; σ) = the denoised output
```

Different papers just used different formulas for c_skip, c_out, c_in, c_noise:

```
┌────────────┬──────────────────┬──────────────────┬──────────────────┐
│            │     VP (DDPM)    │     VE (Song)    │     EDM          │
├────────────┼──────────────────┼──────────────────┼──────────────────┤
│ c_skip     │ 1                │ 1                │ σd²/(σ²+σd²)    │
│ c_out      │ -σ               │ σ                │ σ·σd/√(σ²+σd²)  │
│ c_in       │ 1/√(σ²+1)       │ 1                │ 1/√(σd²+σ²)     │
│ c_noise    │ (M-1)·σ_inv(σ)  │ log(σ/2)         │ log(σ)/4         │
│ Predicts   │ noise ε          │ score ∇log p     │ denoised x₀     │
└────────────┴──────────────────┴──────────────────┴──────────────────┘
  (σd = sigma_data = 0.5)
```

**Contribution 2: Optimal Preconditioning**

EDM derived the **mathematically optimal** values for c_skip, c_out, c_in
based on the principle that:
- The network input should have unit variance (c_in normalizes it)
- The network output should have unit variance (c_out scales it)
- The training target should have unit variance (c_skip ensures this)

This is why EDM's formulas look more complex — they're derived to make
the network's job as easy as possible.

**Contribution 3: Better Sampler**

EDM proposed a new ODE sampler (Algorithm 2 — the Heun sampler) that:
- Works with **any** number of steps (not tied to T=1000)
- Uses 2nd-order corrections (Heun's method) for better accuracy
- Has a better noise schedule for the sampling steps

### 4.2 The EDM Noise Level: Continuous σ

In EDM, noise level is parameterized directly as σ (not as t or β):

```
x_noisy = x_clean + σ × ε    where ε ~ N(0, I)
```

This is the VE formulation — simple addition, no scaling of x_clean.

During training, σ is sampled from a **log-normal distribution**:

```
ln(σ) ~ N(P_mean, P_std²)    where P_mean = -1.2, P_std = 1.2
```

This is what you see in the actual codebase (`EDMLoss.__call__`):

```python
rnd_normal = torch.randn([images.shape[0], 1, 1, 1], device=images.device)
sigma = (rnd_normal * self.P_std + self.P_mean).exp()
#        ↑ sample from N(0,1)                    ↑ exponentiate
# Result: ln(sigma) ~ N(-1.2, 1.2²)
# So sigma itself follows a log-normal distribution
# Most samples fall in [0.01, 10], with peak around σ ≈ 0.3
```

### 4.3 The EDM Training Loop (What CorrDiff Actually Does)

From the actual `EDMLossSR` class in the codebase:

```python
def __call__(self, net, img_clean, img_lr, labels=None, augment_pipe=None):
    # Step 1: Sample random σ from log-normal distribution
    rnd_normal = torch.randn([img_clean.shape[0], 1, 1, 1], device=...)
    sigma = (rnd_normal * self.P_std + self.P_mean).exp()
    
    # Step 2: Compute loss weight (higher weight for informative σ levels)
    weight = (sigma**2 + self.sigma_data**2) / (sigma * self.sigma_data) ** 2
    
    # Step 3: Data augmentation
    y = img_clean  # (after augmentation)
    y_lr = img_lr  # (after augmentation)
    
    # Step 4: Add noise to the clean HR image
    n = torch.randn_like(y) * sigma      # noise = σ × ε
    noisy_hr = y + n                      # x_noisy = x_clean + σ × ε
    
    # Step 5: Model predicts the DENOISED image (not noise!)
    D_yn = net(noisy_hr, y_lr, sigma, labels)
    # Inside net (EDMPrecondSuperResolution):
    #   c_skip × noisy_hr + c_out × UNet(c_in × noisy_hr, c_noise=log(σ)/4)
    # The output D_yn is the model's estimate of the CLEAN image x₀
    
    # Step 6: Compute weighted MSE loss
    loss = weight * ((D_yn - y) ** 2)
    # Target is the CLEAN image, not the noise!
```

**The key difference from DDPM:**

```
DDPM:  model predicts NOISE ε       →  loss = ‖ε - ε̂‖²
EDM:   model predicts CLEAN IMAGE x₀ →  loss = w(σ) × ‖x₀ - x̂₀‖²
```

Both are mathematically equivalent (you can convert between them), but EDM's
formulation with preconditioning is more numerically stable.

### 4.4 The EDM Sampler (Inference/Generation)

This is the **Heun sampler** (Algorithm 2 from the EDM paper). From the actual
`stochastic_sampler` in the codebase:

```python
def stochastic_sampler(net, latents, img_lr, num_steps=18, sigma_min=0.002,
                        sigma_max=800, rho=7, S_churn=0, S_noise=1, ...):
    
    # Step 1: Create the sigma schedule (NOT evenly spaced!)
    step_indices = torch.arange(num_steps)  # [0, 1, 2, ..., 17]
    t_steps = (
        sigma_max^(1/ρ) + step_indices/(num_steps-1) × (sigma_min^(1/ρ) - sigma_max^(1/ρ))
    )^ρ
    # With ρ=7, this creates steps that are denser at low σ:
    # [800, 451, 240, 120, 55, 24, 9.5, 3.5, 1.2, 0.37, 0.11, 0.03, 0.002]
    # More steps where fine details matter!
    
    # Step 2: Start with pure noise scaled by σ_max
    x = latents * t_steps[0]              # x = ε × σ_max ≈ 800 × ε
    
    # Step 3: Iterate from high noise to low noise
    for i, (σ_cur, σ_next) in enumerate(zip(t_steps[:-1], t_steps[1:])):
        
        # Optional: add extra noise (stochastic sampling, "churn")
        γ = S_churn / num_steps
        σ_hat = σ_cur + γ × σ_cur        # slightly increase noise
        x = x + √(σ_hat² - σ_cur²) × S_noise × randn_like(x)
        
        # Euler step: ask model to denoise
        denoised = net(x, img_lr, σ_hat)  # model predicts clean image
        d = (x - denoised) / σ_hat        # "direction" = (noisy - clean) / σ
        x = x + (σ_next - σ_hat) × d      # take a step toward lower noise
        
        # Heun correction (2nd order): ask model again at the new point
        if i < num_steps - 1:
            denoised_2 = net(x, img_lr, σ_next)
            d_2 = (x - denoised_2) / σ_next
            x = x_prev + (σ_next - σ_hat) × (0.5 × d + 0.5 × d_2)
            #                                  ↑ average of two directions
            #                                  (this is what makes it 2nd order)
    
    return x  # final denoised image
```

**Here's where σ is used during inference:**

```
σ is used in THREE places during each sampling step:

1. AS INPUT TO THE MODEL:
   denoised = net(x, img_lr, σ)
   The model needs to know the current noise level to know how to denoise.
   Inside the model: c_noise = log(σ)/4 → sinusoidal embedding → FiLM

2. TO COMPUTE THE DENOISING DIRECTION:
   d = (x - denoised) / σ
   The direction from the current noisy image toward the clean image,
   normalized by the noise level. This is the "score" ∇log p(x; σ).

3. TO TAKE THE STEP:
   x_new = x + (σ_next - σ_cur) × d
   We move along the denoising direction by an amount proportional to
   the change in noise level.
```

**About "N is a parameter we choose":** ✅ YES! In EDM, `num_steps` is a free
parameter. The default is 18, but you can use any number:

```
num_steps = 1    → terrible quality, but instant
num_steps = 18   → good quality (DEFAULT for CorrDiff)
num_steps = 50   → slightly better quality
num_steps = 100  → diminishing returns
num_steps = 1000 → nearly identical to 100, waste of compute
```

Each step requires 2 model forward passes (Euler + Heun correction), so
18 steps = 36 model calls. Compared to DDPM's 1000 calls, this is a huge win.

# Section 5: CorrDiff — What's Special

CorrDiff (Corrective Diffusion) is an **EDM-based super-resolution model** for
weather data. It has two specific differences from vanilla EDM:

### 5.1 Two-Stage Architecture

```
Stage 1: REGRESSION NETWORK (deterministic)
  Input:  Low-resolution weather data (ERA5, ~25km)
  Output: Mean high-resolution prediction (WRF-like, ~4km)
  
  This captures the EXPECTED downscaling — the average answer.

Stage 2: DIFFUSION NETWORK (stochastic)
  Input:  Low-resolution data + residual (HR truth - regression prediction)
  Output: The RESIDUAL (deviations from the mean)
  
  This captures the UNCERTAINTY — the fine-grained details that
  the regression network can't predict deterministically.
```

The final prediction = regression output + diffusion output.

This is visible in the `ResidualLoss` class in the codebase:

```python
class ResidualLoss:
    def __call__(self, net, img_clean, img_lr, ...):
        # First: compute the mean prediction using the regression network
        y_mean = self.regression_net(torch.zeros_like(y), y_lr, ...)
        
        # Then: compute the RESIDUAL (what's left to predict)
        y = y - y_mean    # ← residual = clean_HR - regression_prediction
        
        # Now train the diffusion model on the RESIDUAL
        sigma = (rnd_normal * self.P_std + self.P_mean).exp()
        latent = y + torch.randn_like(y) * sigma    # add noise to residual
        D_yn = net(latent, y_lr, sigma, ...)         # predict clean residual
        loss = weight * ((D_yn - y) ** 2)            # loss on residual
```

### 5.2 Conditional Super-Resolution

The diffusion model receives the low-resolution image as **conditioning**:

```
Standard EDM:     D(x_noisy, σ)              ← unconditional
CorrDiff:         D(x_noisy, img_lr, σ)      ← conditioned on LR image

Inside EDMPrecondSuperResolution.forward():
  arg = cat(c_in × x_noisy, img_lr)   ← concatenate HR and LR along channels
  F_x = UNet(arg, c_noise)            ← UNet sees both HR and LR
```

This is different from text-conditioned models (Stable Diffusion uses
cross-attention for text conditioning). CorrDiff uses simple **channel
concatenation** because the LR image has the same spatial dimensions as the
HR image.

# Section 6: Other Famous Diffusion Models — How They Differ

### 6.1 DDIM (Song et al., 2020)

**"Denoising Diffusion Implicit Models"**

Same training as DDPM, but a **deterministic** sampler:

```
DDPM sampling:  x_{t-1} = denoise(x_t) + σₜ × z    (z is random noise)
DDIM sampling:  x_{t-1} = denoise(x_t)              (NO added noise)
```

Key innovation: **You can skip steps.** Instead of going t=1000→999→998→...→0,
you can go t=1000→900→800→...→0 (only 10 steps). Same model, different sampler.

This was the first model that decoupled training steps from inference steps.

### 6.2 Stable Diffusion / Latent Diffusion (Rombach et al., 2022)

**"High-Resolution Image Synthesis with Latent Diffusion Models"**

The key trick: run diffusion in a **compressed latent space** instead of
pixel space:

```
Standard diffusion:  noise → denoise → denoise → ... → pixel image
                     operates on 512×512×3 = 786,432 dimensions

Latent diffusion:    noise → denoise → denoise → ... → latent → DECODE → pixel image
                     operates on 64×64×4 = 16,384 dimensions (48× smaller!)
```

Architecture:
```
Encoder (pretrained VAE):  pixel image → latent (compression)
Diffusion (UNet):          operates only in latent space
Decoder (pretrained VAE):  latent → pixel image (decompression)
```

Stable Diffusion also uses **cross-attention** for text conditioning
(not channel concatenation like CorrDiff).

### 6.3 DALL-E 2 (Ramesh et al., 2022)

Uses a two-stage approach:
1. CLIP text encoder → text embedding
2. Diffusion "prior" → image embedding from text embedding
3. Diffusion "decoder" → image from image embedding

### 6.4 Consistency Models (Song et al., 2023)

Train the model to map ANY point on the noise trajectory directly to x₀ in
**one step**. No iterative denoising needed. Much faster but lower quality.

### 6.5 Flow Matching / Rectified Flow (Lipman et al., 2023)

Instead of the complex SDE formulation, use simple straight-line interpolation:

```
Diffusion SDE:    curved path from noise to data
Flow Matching:    STRAIGHT path from noise to data
```

Simpler math, faster training, easier to understand. Used in newer models
like Stable Diffusion 3 and Flux.

# Section 7: The Complete Picture — Training vs Inference

Let me put EVERYTHING together in one unified view:

## Training (All Variants)

```
┌──────────────────────────────────────────────────────────────────────┐
│                    TRAINING (all variants)                            │
│                                                                      │
│  The core loop is ALWAYS the same:                                  │
│                                                                      │
│  1. Get a clean image x₀                                            │
│  2. Pick a noise level:                                             │
│       DDPM:     t ~ Uniform{1,...,T}  then compute σ = f(t)         │
│       EDM:      σ ~ LogNormal(-1.2, 1.2²)                          │
│       CorrDiff: same as EDM, but x₀ = residual (HR - regression)   │
│                                                                      │
│  3. Add noise:                                                      │
│       DDPM:     x_t = √ᾱₜ × x₀ + √(1-ᾱₜ) × ε                    │
│       EDM:      x_noisy = x₀ + σ × ε                               │
│       CorrDiff: same as EDM                                         │
│                                                                      │
│  4. Model predicts:                                                 │
│       DDPM:     ε̂ = model(x_t, t)          → predicts NOISE        │
│       EDM:      x̂₀ = model(x_noisy, σ)    → predicts CLEAN IMAGE  │
│       CorrDiff: x̂₀ = model(x_noisy, img_lr, σ) → predicts CLEAN  │
│                                                                      │
│  5. Compute loss:                                                   │
│       DDPM:     L = ‖ε - ε̂‖²                                       │
│       EDM:      L = w(σ) × ‖x₀ - x̂₀‖²                             │
│       CorrDiff: same as EDM                                         │
│                                                                      │
│  Training is ALWAYS a single forward + backward pass.               │
│  NO iteration. ONE random noise level per sample.                   │
└──────────────────────────────────────────────────────────────────────┘
```

## Inference/Generation (All Variants)

```
┌──────────────────────────────────────────────────────────────────────┐
│                  INFERENCE (all variants)                             │
│                                                                      │
│  The core loop is ALWAYS the same:                                  │
│                                                                      │
│  1. Start from pure noise:                                          │
│       DDPM:     x_T ~ N(0, I)                                      │
│       EDM:      x ~ N(0, σ_max² × I)                               │
│       CorrDiff: x ~ N(0, σ_max² × I)  (the residual starts as noise)│
│                                                                      │
│  2. Create a schedule of noise levels:                              │
│       DDPM:     [T, T-1, T-2, ..., 1]        (1000 steps, fixed)   │
│       DDIM:     [T, T-k, T-2k, ...]          (fewer steps, skip)   │
│       EDM:      [σ_max, ..., σ_min]           (18 steps, flexible)  │
│       CorrDiff: same as EDM                                         │
│                                                                      │
│  3. For each step, go from current noise level to next:             │
│       DDPM:     x_{t-1} = denoise_step(x_t, t)                     │
│       EDM:      x_new = heun_step(x, σ_cur, σ_next)                │
│       CorrDiff: x_new = heun_step(x, img_lr, σ_cur, σ_next)       │
│                                                                      │
│     Inside each step:                                               │
│       a. Model predicts denoised image                              │
│       b. Compute direction toward clean image                       │
│       c. Take a step in that direction                              │
│       d. (Optional) Add small noise for stochasticity               │
│                                                                      │
│  4. Return final image:                                             │
│       DDPM/EDM: x₀ ← the generated image                           │
│       CorrDiff: x₀ + regression_prediction ← add back the mean     │
│                                                                      │
│  Total model calls:                                                 │
│       DDPM:     1000                                                │
│       DDIM:     10-100                                              │
│       EDM:      36 (18 steps × 2 for Heun)                         │
│       CorrDiff: 36 (same as EDM)                                   │
└──────────────────────────────────────────────────────────────────────┘
```

# Section 8: Summary Cheat Sheet

## Your Original Questions — Answered

| Your statement | Correct? | Actual answer |
|---|---|---|
| "We take clean image then generate random noise" | ✅ | Yes — sample ε ~ N(0,I), scale by σ |
| "For discrete we take random step id" | ✅ | Yes — t ~ Uniform{1,...,T} |
| "We generate noise using the formula" | ✅ | x_t = √ᾱₜ x₀ + √(1-ᾱₜ) ε (DDPM) or x = x₀ + σε (EDM) |
| "We add it to the clean image" | ✅ | Yes |
| "We train the model to remove noise in one step" | ⚠️ Partial | Model predicts NOISE (DDPM) or CLEAN IMAGE (EDM), not x_{t-1} |
| "We train it to move to step i-1" | ❌ | Model predicts ε or x₀. The step-back formula is separate. |
| "Training is always one step" | ✅ | Yes — one forward pass, one noise level |
| "We choose random step from 1 to n" | ✅ | Discrete: t from {1,...,T}. Continuous: σ from distribution. |
| "In production we repeat n times" | ✅ | Yes — n is configurable in EDM (default 18 for CorrDiff) |
| "Model predicts noise, we remove it" | ⚠️ | DDPM: predicts noise. EDM/CorrDiff: predicts denoised image. |
| "We add small extra noise" | ✅ | Yes (if S_churn > 0 in EDM, or always in DDPM) |
| "For continuous I have no idea" | — | Answered in Section 3: continuous σ instead of discrete t |
| "I don't know where σ is used in inference" | — | Answered in Section 4.4: used as model input, in direction computation, and in step size |

## EDM At a Glance

```
EDM = "Elucidating the Design Space of Diffusion-Based Generative Models"
      ↓
A FRAMEWORK (not a model) that:
  1. Unifies VP, VE, DDPM, Score-SDE under one notation
  2. Derives optimal preconditioning (c_skip, c_out, c_in, c_noise)
  3. Proposes efficient Heun sampler (18 steps instead of 1000)
  4. Uses continuous σ from log-normal distribution
  5. Model predicts denoised image x₀ (not noise ε)
      ↓
CorrDiff uses EDM because:
  - Flexible step count at inference
  - Mathematically principled preconditioning
  - Clean extension to super-resolution
  - State-of-the-art quality at time of development
```
