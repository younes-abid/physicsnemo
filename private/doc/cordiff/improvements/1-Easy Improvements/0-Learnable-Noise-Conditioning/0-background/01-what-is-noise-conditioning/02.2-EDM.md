# Section 1: Why EDM Exists — The Problem It Solves

## 1.1 The Messy State of Diffusion Models Before EDM

By 2022, there were many diffusion model variants, and they all seemed
different:

```
DDPM (Ho et al., 2020):
  - Predicts NOISE ε
  - Uses discrete timesteps t ∈ {1, ..., 1000}
  - Variance schedule β₁, β₂, ..., βT
  - Forward: x_t = √ᾱₜ × x₀ + √(1-ᾱₜ) × ε

Score SDE — VP (Song et al., 2021):
  - Predicts SCORE ∇log p(x)
  - Uses continuous time t ∈ [0, 1]
  - Variance Preserving formulation
  - Forward: same as DDPM but continuous

Score SDE — VE (Song et al., 2021):
  - Predicts SCORE ∇log p(x)
  - Uses continuous time t ∈ [0, 1]
  - Variance Exploding formulation
  - Forward: x(t) = x₀ + σ(t) × ε

iDDPM (Nichol & Dhariwal, 2021):
  - Predicts NOISE ε
  - Also predicts the VARIANCE (learned)
  - Cosine noise schedule
```

If you were a researcher in 2022 and wanted to build a diffusion model, you'd
face an overwhelming number of choices:
- What should my model predict? (noise ε? clean image x₀? score ∇log p?)
- How should I scale my inputs and outputs?
- What noise schedule should I use?
- How should I sample at inference time?
- How many steps do I need?

**Every paper made different choices, and it was impossible to tell which
choices actually mattered and which were arbitrary.**

## 1.2 The Restaurant Analogy 🍽️

Imagine you're comparing three restaurants. Each one claims to have the
"best pasta":

```
Restaurant A (DDPM):
  - Uses brand X flour, brand Y tomatoes
  - Cooks at 180°C for 25 minutes
  - Serves on a white plate

Restaurant B (Score SDE VP):
  - Uses brand Z flour, brand W tomatoes
  - Cooks at 190°C for 22 minutes
  - Serves on a blue plate

Restaurant C (Score SDE VE):
  - Uses brand X flour, brand W tomatoes
  - Cooks at 175°C for 28 minutes
  - Serves on a wooden board
```

Which restaurant is best? Hard to say — they each changed MULTIPLE things.
You can't tell if Restaurant A is better because of its flour, its temperature,
or its plate.

**EDM is like a food scientist who says:**

> "Wait — I'll show you that ALL three restaurants are actually using the
> same recipe, just with different flour brands and oven temperatures. Once
> you see that, I can systematically test each choice and tell you the
> OPTIMAL combination."

That's exactly what Karras et al. did. They showed all diffusion models
share a common structure, then found the best settings.

# Section 2: The Unified Framework — One Formula to Rule Them All

## 2.1 The Universal Denoiser Equation

EDM's first contribution: every diffusion model can be written as:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  D(x; σ) = c_skip(σ) × x  +  c_out(σ) × F_θ(c_in(σ) × x; c_noise(σ))│
│                                                                         │
│  ─────────────────────   ────────────────────────────────────────────   │
│  SKIP CONNECTION          NETWORK PREDICTION (scaled)                   │
│  "keep some of the        "add the network's correction"               │
│   noisy input as-is"                                                    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

Let me explain every piece:

| Symbol | What it is | Plain English |
|--------|-----------|---------------|
| **x** | Noisy input image | What you feed in (image + noise) |
| **σ** | Noise level | How much noise is in x (a single number) |
| **F_θ** | The raw neural network (UNet) | The actual learnable model with weights θ |
| **c_skip(σ)** | Skip connection weight | "How much of the raw noisy input to keep" |
| **c_out(σ)** | Output scaling | "How much to scale the network's output" |
| **c_in(σ)** | Input scaling | "How much to scale the input before feeding to the network" |
| **c_noise(σ)** | Noise conditioning label | "What to tell the network about the current noise level" |
| **D(x; σ)** | Final denoised output | The model's prediction of the clean image |

## 2.2 The Thermostat Analogy 🌡️

Think of this like a smart thermostat system:

```
YOUR ROOM (the noisy image x):
  Currently at some temperature (mix of signal + noise)

THE THERMOSTAT SYSTEM:

  1. SENSOR (c_in):
     Normalizes the temperature reading so the controller can understand it.
     "The room is at 25°C" → sensor converts to a 0-1 scale → "0.73"

  2. CONTROLLER BRAIN (F_θ — the UNet):
     Takes the normalized reading + knows the outdoor conditions (c_noise)
     Decides what correction is needed.
     "Based on normalized reading 0.73 and outdoor temp, adjust by -0.15"

  3. OUTPUT AMPLIFIER (c_out):
     Scales the controller's decision to actual heating/cooling power.
     "-0.15" → amplified to → "-3°C of cooling"

  4. BASELINE (c_skip):
     "Even without any correction, keep the room at its current temp"
     Passes through the current temperature.

  5. FINAL RESULT (D):
     Final temperature = c_skip × current + c_out × controller_decision
     = 0.8 × 25°C + (-3°C) = 17°C  (the target comfortable temperature)
```

The key insight: **different thermostat brands (DDPM, VE, VP) all have these
same components — they just calibrate the sensor, amplifier, and baseline
differently!**

## 2.3 How Each Model Fits Into This Framework

Here's the table that shows the EDM unification. Each row is a different
"calibration" of the same system:

```
┌────────────────┬───────────────────┬───────────────────┬───────────────────┐
│                │   VP (DDPM)       │   VE (Song)       │   EDM (optimal)   │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ c_skip(σ)      │ 1                 │ 1                 │ σd²/(σ²+σd²)     │
│                │ "always keep      │ "always keep      │ "keep MORE input  │
│                │  full input"      │  full input"      │  when noise is    │
│                │                   │                   │  LOW (σ small)"   │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ c_out(σ)       │ -σ                │ σ                 │ σ·σd/√(σ²+σd²)   │
│                │ "negate the noise │ "scale by noise   │ "optimal scaling  │
│                │  prediction"      │  level"           │  that normalizes  │
│                │                   │                   │  target variance" │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ c_in(σ)        │ 1/√(σ²+1)        │ 1                 │ 1/√(σd²+σ²)      │
│                │ "normalize by     │ "no scaling"      │ "normalize so     │
│                │  total variance"  │                   │  input has unit   │
│                │                   │                   │  variance"        │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ c_noise(σ)     │ (M-1)·σ_inv(σ)   │ log(σ/2)          │ log(σ)/4          │
│                │ "convert σ back   │ "log of noise     │ "log of noise     │
│                │  to discrete t"   │  level"           │  level / 4"       │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ What F_θ       │ noise ε           │ score ∇log p      │ denoised x₀      │
│ predicts       │                   │                   │ (with precond.)   │
├────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ Where σd =     │ (not used)        │ (not used)        │ 0.5 (sigma_data)  │
│ sigma_data     │                   │                   │                   │
└────────────────┴───────────────────┴───────────────────┴───────────────────┘
```

**σd (sigma_data) = 0.5** is a key EDM hyperparameter. It represents the
expected standard deviation of the training data (after normalization). If your
training images have pixel values roughly in [-1, 1], then std ≈ 0.5 is a
reasonable estimate.

## 2.4 Where This Lives in the Actual Codebase

The preconditioning classes are in:
`physicsnemo/models/diffusion/preconditioning.py`

Here are the ACTUAL forward methods, side by side:

**VP Preconditioning** (`VPPrecond.forward`):
```python
c_skip = 1
c_out = -sigma
c_in = 1 / (sigma**2 + 1).sqrt()
c_noise = (self.M - 1) * self.sigma_inv(sigma)
```

**VE Preconditioning** (`VEPrecond.forward`):
```python
c_skip = 1
c_out = sigma
c_in = 1
c_noise = (0.5 * sigma).log()
```

**EDM Preconditioning** (`EDMPrecond.forward` and `EDMPrecondSuperResolution.forward`):
```python
c_skip = self.sigma_data**2 / (sigma**2 + self.sigma_data**2)
c_out = sigma * self.sigma_data / (sigma**2 + self.sigma_data**2).sqrt()
c_in = 1 / (self.sigma_data**2 + sigma**2).sqrt()
c_noise = sigma.log() / 4
```

And they ALL end the same way:
```python
F_x = self.model(c_in * x, c_noise, ...)   # Run the UNet
D_x = c_skip * x + c_out * F_x             # Combine skip + prediction
return D_x
```

**Same structure, different constants.** That's the EDM unification.

# Section 3: Why Preconditioning Matters — The Core Insight

## 3.1 The Problem Without Preconditioning

Imagine you're a neural network (the UNet F_θ), and you receive inputs at
wildly different scales:

```
When σ = 0.002 (almost clean):
  x_noisy ≈ x_clean + tiny noise
  The input pixels are in range [-1, 1]
  You need to make a TINY correction (remove 0.2% noise)

When σ = 80 (almost pure noise):
  x_noisy ≈ 80 × random_noise
  The input pixels are in range [-240, 240]    ← 240× LARGER!
  You need to basically GUESS the entire image from scratch
```

**The input scale varies by 40,000× across the σ range!** Without
preconditioning, the network has to simultaneously handle inputs from [-1, 1]
AND inputs from [-240, 240]. This is like asking someone to be equally good at
hearing a whisper and a jet engine — the dynamic range is too large.

## 3.2 The Sound Engineer Analogy 🎧

Imagine you're a sound engineer recording both:
- A quiet whisper (amplitude 0.001)
- A rock concert (amplitude 100.0)

**Without preconditioning** (bad approach):
```
Record everything with the same microphone sensitivity.
Result: The whisper is invisible in the recording (lost in static),
        and the concert clips and distorts.
```

**With preconditioning** (EDM approach):
```
Before recording:
  - Amplify the whisper by 1000× → now it's at amplitude 1.0
  - Attenuate the concert by 100× → now it's at amplitude 1.0

Record everything — both sources are now at a comfortable level.

After recording:
  - Reverse the amplification on playback

Result: Both whisper and concert are perfectly captured.
```

**That's exactly what c_in, c_out, and c_skip do:**

```
c_in  = the INPUT microphone gain    → normalizes the noisy image
c_out = the OUTPUT volume knob       → scales the network's prediction
c_skip = the "pass-through" channel  → how much raw input to keep
```

## 3.3 What Each Preconditioning Coefficient Does (In Detail)

### c_in — Input Normalization

```
c_in(σ) = 1 / √(σd² + σ²)

Purpose: Make the input to F_θ have approximately UNIT VARIANCE,
         regardless of the noise level σ.
```

Why does this work? The noisy input is:
```
x_noisy = x_clean + σ × ε

Variance of x_noisy = Var(x_clean) + σ² × Var(ε)
                    = σd²           + σ²
                    = σd² + σ²

After scaling by c_in:
  Var(c_in × x_noisy) = c_in² × (σd² + σ²)
                       = (1/(σd² + σ²)) × (σd² + σ²)
                       = 1    ← unit variance! ✅
```

**Analogy:** Before taking an exam, all students normalize their scores to
a 0-100 scale. Whether the original was out of 10 or out of 1000 doesn't
matter — the normalized score is always comparable.

### c_skip — The Skip Connection Weight

```
c_skip(σ) = σd² / (σ² + σd²)

Purpose: When noise is LOW (σ ≈ 0), the noisy input is ALMOST the clean
         image. So just pass it through! Don't make the network do work
         that's already done.
```

Behavior:
```
σ ≈ 0    (clean):   c_skip ≈ σd²/σd² = 1.0   → "Keep 100% of input"
                     (the input IS the answer!)

σ = σd   (medium):  c_skip = σd²/2σd² = 0.5   → "Keep 50% of input"
                     (half signal, half noise)

σ → ∞    (pure noise): c_skip → 0              → "Ignore the input"
                     (it's all noise, useless!)
```

**Analogy:** If someone gives you a rough draft of an essay:
- If it's 95% done → keep most of it, just fix typos (c_skip ≈ 1)
- If it's 50% done → keep the good parts, rewrite the rest (c_skip ≈ 0.5)
- If it's total gibberish → throw it away and write from scratch (c_skip ≈ 0)

### c_out — Output Scaling

```
c_out(σ) = σ × σd / √(σ² + σd²)

Purpose: Scale the network's output so that the TRAINING TARGET
         (what F_θ needs to predict) has approximately unit variance.
```

This is the trickiest one. The training target for F_θ is:
```
target = (x_clean - c_skip × x_noisy) / c_out
```

EDM derived c_out so that Var(target) ≈ 1 for all σ. This means the
network always predicts values in a comfortable range, regardless of
the noise level.

**Analogy:** If you're teaching someone to throw darts:
- At 1 meter away, a "good throw" means hitting within 1 cm
- At 10 meters away, a "good throw" means hitting within 10 cm
- c_out adjusts the "scoring scale" so that a good throw always scores ~1 point,
  regardless of distance. This makes learning consistent.

### c_noise — The Noise Label

```
c_noise(σ) = log(σ) / 4

Purpose: Convert σ to a number that the network can use as a
         "which noise level am I at?" indicator.
```

Why log(σ)/4?
```
σ ranges from 0.002 to 80 → ratio of 40,000×
log(σ) ranges from -6.2 to 4.4 → a nice, compact range
log(σ)/4 ranges from -1.55 to 1.1 → even more compact

This compressed value gets fed into a sinusoidal embedding
(see Part 4: Sinusoidal Embeddings), which converts it into a
rich vector that the UNet can use.
```

**Analogy:** Instead of telling someone "the distance is 0.003 km" or
"the distance is 120 km" (wildly different scales), you say "the distance
on a 1-10 scale is 1" or "the distance on a 1-10 scale is 8." The log
transform compresses the huge range into a manageable one.

# Section 4: EDM Training — Step by Step

## 4.1 The Training Loop

Here's exactly what happens during one training iteration:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         EDM TRAINING LOOP                                │
│                                                                          │
│  For each batch of training data:                                       │
│                                                                          │
│  ① SAMPLE a clean image from the dataset                                │
│     x₀ ~ p_data                                                        │
│                                                                          │
│  ② SAMPLE a random noise level from a log-normal distribution           │
│     ln(σ) ~ N(P_mean, P_std²)                                          │
│     where P_mean = -1.2, P_std = 1.2                                   │
│                                                                          │
│  ③ SAMPLE random noise                                                  │
│     ε ~ N(0, I)    (same shape as the image)                            │
│                                                                          │
│  ④ CREATE the noisy image                                               │
│     x_noisy = x₀ + σ × ε                                               │
│                                                                          │
│  ⑤ RUN the model (with preconditioning)                                 │
│     x̂₀ = D(x_noisy; σ)                                                │
│        = c_skip(σ) × x_noisy + c_out(σ) × F_θ(c_in(σ) × x_noisy; σ)  │
│                                                                          │
│  ⑥ COMPUTE the weighted loss                                            │
│     L = w(σ) × ‖x₀ - x̂₀‖²                                            │
│     where w(σ) = (σ² + σd²) / (σ × σd)²                               │
│                                                                          │
│  ⑦ BACKPROPAGATE and update weights                                     │
│                                                                          │
│  That's it! ONE forward pass, ONE noise level, ONE gradient step.       │
└──────────────────────────────────────────────────────────────────────────┘
```

## 4.2 Why Log-Normal Sampling for σ?

The noise level σ is NOT sampled uniformly. It's sampled from a
**log-normal distribution**:

```python
# From the actual codebase (EDMLoss / EDMLossSR):
rnd_normal = torch.randn([batch_size, 1, 1, 1])   # sample from N(0,1)
sigma = (rnd_normal * self.P_std + self.P_mean).exp()
#        ↑ shift & scale to N(P_mean, P_std²)  ↑ exponentiate
# Result: ln(σ) ~ N(-1.2, 1.2²)
```

What does this distribution look like?

```
Probability
  │
  │    ╭──╮
  │   ╭╯  ╰╮
  │  ╭╯    ╰──╮
  │ ╭╯        ╰───╮
  │╭╯              ╰────────╮
  ├╯                        ╰──────────────────
  └──────────┼──────────┼──────────┼──────────→ σ
           0.01       0.3        10          80

  Peak ≈ 0.3 (most training samples see moderate noise)
  Long tail to the right (some samples see very high noise)
  Short tail to the left (few samples see very low noise)
```

**Why not uniform?**

```
UNIFORM sampling of σ ∈ [0.002, 80]:
  Most samples would be σ > 40 (high noise)
  Very few samples would be σ < 1 (low noise)
  → The model barely sees low-noise cases
  → Fine details are never learned properly

LOG-NORMAL sampling:
  Concentrates most samples around σ ≈ 0.3
  But still gives reasonable coverage of all noise levels
  → The model sees all noise levels in roughly balanced proportion
  → Better learning across the full range
```

**Analogy:** If you're training a pianist, you wouldn't spend 90% of practice
on the hardest pieces (high σ) and 10% on everything else. You'd spend most
time on moderate difficulty, with some time on easy and hard pieces. The
log-normal distribution does exactly this.

## 4.3 The Loss Weight w(σ)

```
w(σ) = (σ² + σd²) / (σ × σd)²
```

This weight makes the loss contribution approximately EQUAL across all
noise levels. Without it:

```
At σ = 0.002 (clean):  Error is tiny → loss is tiny → no gradient signal
At σ = 80 (noisy):     Error is huge → loss is huge → dominates training

With w(σ):
  At σ = 0.002: w ≈ 1,000,000 → amplifies the tiny error
  At σ = 80:    w ≈ 0.00025   → dampens the huge error
  At σ = 0.5:   w ≈ 4         → moderate
```

**Analogy:** In a classroom, the quiet student who whispers correct answers
(low σ) and the loud student who shouts wrong answers (high σ) should both
be heard equally. The weight w(σ) is like adjusting everyone's microphone
volume so the teacher hears each student at the same level.

# Section 5: EDM Inference — The Heun Sampler

## 5.1 The Big Picture

During inference, we have NO clean image. We start from pure noise and
iteratively denoise:

```
Pure noise (σ = 800) → ... → moderate noise (σ = 1) → ... → clean image (σ = 0.002)

Each arrow = one denoising step using the trained model
```

## 5.2 The Sigma Schedule (Choosing the Steps)

The first question: at which noise levels do we evaluate? EDM uses a
clever non-uniform schedule:

```python
# From the codebase (stochastic_sampler):
step_indices = torch.arange(num_steps)  # [0, 1, 2, ..., N-1]
t_steps = (
    sigma_max**(1/rho) + step_indices/(num_steps-1)
    * (sigma_min**(1/rho) - sigma_max**(1/rho))
)**(rho)
# Default: rho = 7, sigma_max = 800, sigma_min = 0.002, num_steps = 18
```

With the default settings (18 steps, ρ=7), the schedule looks like:

```
Step:  0      1     2     3     4     5     6     7     8
σ:    800   451   240   120    55    24   9.5   3.5   1.2

Step:  9     10    11    12    13    14    15    16    17
σ:    0.37  0.11  0.03  0.01  0.005 0.003 0.002 0.002 0.0

Notice: steps are MUCH denser at low σ (fine details)
        and sparser at high σ (global structure)
```

**Why non-uniform spacing?**

```
HIGH σ (global structure):
  At σ = 800, the image is nearly pure noise.
  At σ = 400, it's... still nearly pure noise.
  Not much changes between these two → large steps are fine.

LOW σ (fine details):
  At σ = 0.1, you can see fine textures.
  At σ = 0.01, those textures are sharper.
  Subtle changes happen here → need small steps to capture them.
```

**Analogy — Sculpting a statue:** 🗿
- First passes (high σ): You chisel the rough shape — big chunks of marble
  fly off. You don't need precision; you just need the general form.
  → Large σ steps (800 → 451 → 240)
- Middle passes (medium σ): You define the features — the face, the hands.
  → Medium σ steps (24 → 9.5 → 3.5)
- Final passes (low σ): You polish and refine — individual eyelashes, skin
  texture. This requires the most care and the smallest movements.
  → Tiny σ steps (0.11 → 0.03 → 0.01 → 0.005)

The ρ=7 schedule automatically creates this sculpture-like progression.

## 5.3 The Euler Step (1st Order)

At each step, we need to go from σ_cur to σ_next (a lower noise level).
The simplest approach is the **Euler step**:

```
Step 1: Ask the model to denoise
  x̂₀ = D(x, σ_cur)                    ← "what does the clean image look like?"

Step 2: Compute the denoising direction
  d = (x - x̂₀) / σ_cur               ← "which direction is noise → clean?"

Step 3: Take a step along that direction
  x_next = x + (σ_next - σ_cur) × d   ← "move toward cleaner"
```

**Why (x - x̂₀) / σ?** This is the **score function** ∇log p(x; σ).
Intuitively:
```
x       = noisy image (signal + noise)
x̂₀     = model's guess of the clean image (signal only)
x - x̂₀ = the noise component
(x - x̂₀) / σ = noise normalized by noise level = "direction of maximum noise"

Moving in the OPPOSITE direction → removes noise
```

**Analogy — GPS navigation:** 🧭
- You're at position x (noisy image)
- Your destination is x̂₀ (clean image)
- The direction d = (x - x̂₀)/σ tells you which way to go
- You take a step proportional to (σ_next - σ_cur) — since σ is decreasing,
  this is a negative number, so you move TOWARD the clean image

## 5.4 The Heun Correction (2nd Order) — EDM's Innovation

The Euler step is like walking with a compass that you only check at the
START of each step. If the terrain curves, you'll drift off course.

The **Heun correction** checks the compass TWICE — once at the start and
once at the end — then averages:

```
Step 1: Euler step (same as above)
  x̂₀ = D(x, σ_cur)
  d₁ = (x - x̂₀) / σ_cur
  x_euler = x + (σ_next - σ_cur) × d₁

Step 2: Heun correction (ask the model AGAIN at the new point)
  x̂₀' = D(x_euler, σ_next)           ← second model call!
  d₂ = (x_euler - x̂₀') / σ_next

Step 3: Average the two directions
  d_avg = (d₁ + d₂) / 2
  x_next = x + (σ_next - σ_cur) × d_avg
```

**Why is this better?**

```
EULER (1st order):          HEUN (2nd order):

Start ──── d₁ ───→ End     Start ──── d₁ ───→ Tentative End
                                                    │
     (might overshoot          Check direction d₂ at End
      or undershoot)                    │
                            Average d₁ and d₂
                                    │
                            Start ── d_avg ──→ Better End
```

**Analogy — Crossing a river:** 🏞️
- **Euler:** You look at the current at the near bank, estimate how it'll
  push you, and swim. But the current might change mid-river, so you
  end up downstream of your target.
- **Heun:** You swim to where you THINK you should end up, then check
  the current THERE too. You average both currents and re-swim. You end
  up much closer to your target.

**Cost:** Heun uses 2 model calls per step instead of 1. So 18 Heun steps
= 36 model forward passes. Still way better than DDPM's 1000 calls!

## 5.5 Stochastic Sampling (Optional Noise Injection)

EDM also supports adding a small amount of fresh noise at each step
(controlled by `S_churn`):

```python
# Optional: add extra noise ("churn")
gamma = min(S_churn / num_steps, sqrt(2) - 1)
sigma_hat = sigma_cur + gamma * sigma_cur      # slightly increase σ
x = x + sqrt(sigma_hat**2 - sigma_cur**2) * S_noise * randn_like(x)
```

```
S_churn = 0   → deterministic sampling (same noise → same output every time)
S_churn > 0   → stochastic sampling (adds randomness → different outputs)
```

**Why add noise if we're trying to REMOVE noise?**

```
WITHOUT stochastic noise:
  If the model makes a small error at step 5, that error ACCUMULATES
  through all remaining steps. Errors compound.

WITH stochastic noise:
  The added noise "jiggles" the trajectory slightly, which can help
  the model correct previous errors. It's like giving the model a
  fresh start at each step.
```

**Analogy — Shaking a jigsaw puzzle:** 🧩
If you're assembling a puzzle and some pieces are slightly misaligned,
a gentle shake can help pieces fall into their correct positions. Too
much shaking scatters everything (bad). A tiny shake helps (good).

## 5.6 The Complete Sampling Algorithm

Putting it all together:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                    EDM SAMPLING (Algorithm 2 from the paper)             │
│                                                                          │
│  INPUTS:                                                                │
│    - Trained model D(x; σ)                                              │
│    - num_steps = 18 (default)                                           │
│    - sigma_max = 800, sigma_min = 0.002                                 │
│    - rho = 7 (schedule curvature)                                       │
│    - S_churn, S_noise (stochasticity controls)                          │
│                                                                          │
│  PROCEDURE:                                                             │
│                                                                          │
│  1. Create σ schedule: [σ₀, σ₁, ..., σ_{N-1}, 0]                       │
│     using the power-law formula with ρ=7                                │
│                                                                          │
│  2. Sample initial noise: x ← σ₀ × ε,  ε ~ N(0, I)                    │
│                                                                          │
│  3. For i = 0, 1, ..., N-1:                                            │
│                                                                          │
│     a. (Optional) Add stochastic noise:                                 │
│        σ̂ᵢ = σᵢ + γ × σᵢ                                               │
│        x ← x + √(σ̂ᵢ² - σᵢ²) × noise                                  │
│                                                                          │
│     b. Euler step:                                                      │
│        x̂₀ = D(x; σ̂ᵢ)               ← MODEL CALL #1                   │
│        d₁ = (x - x̂₀) / σ̂ᵢ                                            │
│        x_next = x + (σᵢ₊₁ - σ̂ᵢ) × d₁                                 │
│                                                                          │
│     c. Heun correction (if not last step):                              │
│        x̂₀' = D(x_next; σᵢ₊₁)       ← MODEL CALL #2                   │
│        d₂ = (x_next - x̂₀') / σᵢ₊₁                                    │
│        x_next = x + (σᵢ₊₁ - σ̂ᵢ) × (d₁ + d₂) / 2                     │
│                                                                          │
│     d. x ← x_next                                                      │
│                                                                          │
│  4. Return x  ← the generated image                                    │
│                                                                          │
│  Total model calls: 2×(N-1) + 1 = 2×17 + 1 = 35 for N=18             │
│  Compare to DDPM: 1000 calls. EDM is ~28× faster!                      │
└──────────────────────────────────────────────────────────────────────────┘
```

# Section 6: The Noise Schedule — σ_min, σ_max, and Everything Between

## 6.1 What σ_min and σ_max Mean

```
σ_min = 0.002
  The LOWEST noise level. Below this, the model considers the image "clean."
  Noise at this level is essentially invisible:
  pixel value 0.5 + 0.002 × noise ≈ 0.5 (unchanged)

σ_max = 80 (training) or 800 (sampling)
  The HIGHEST noise level. At this level, the image is PURE noise:
  pixel value 0.5 + 80 × noise ≈ 80 × noise (signal is negligible)
```

**Why is σ_max different for training vs sampling?**

During training, σ is sampled from a log-normal distribution centered
around σ ≈ 0.3. Very few samples have σ > 80, so the model rarely sees
σ = 800. But during sampling, we START at σ_max. Using σ_max = 800 gives
the model a "running start" — it begins from pure noise and has more room
to gradually denoise. The model generalizes well to these extreme σ values
even though it rarely saw them during training.

## 6.2 The Signal-to-Noise Ratio (SNR)

σ is directly related to the signal-to-noise ratio:

```
SNR = σd² / σ²

When σ << σd:  SNR >> 1  → mostly signal (clean)
When σ = σd:   SNR = 1   → equal signal and noise
When σ >> σd:  SNR << 1  → mostly noise (corrupted)
```

The preconditioning coefficients are all functions of the SNR:
```
c_skip = 1 / (1 + 1/SNR)     → approaches 1 when SNR is high
c_out  = 1 / √(1 + SNR)      → approaches 0 when SNR is high
c_in   = √(SNR) / σd / √(1 + SNR)  → normalizes input variance
```

This is why EDM works so well: the preconditioning adapts smoothly to
the signal-to-noise ratio.

# Section 7: CorrDiff — How It Extends EDM

## 7.1 From Unconditional to Conditional Super-Resolution

Standard EDM generates images from scratch — there's no input image.
CorrDiff adapts EDM for **conditional super-resolution**: given a
low-resolution weather map, generate a plausible high-resolution version.

```
Standard EDM:
  D(x; σ)           ← just noisy image + noise level
  
CorrDiff EDM:
  D(x, img_lr; σ)   ← noisy HR image + LR conditioning image + noise level
```

The change is simple — concatenate the LR image to the input channels:

```python
# From EDMPrecondSuperResolution.forward():
c_in = 1 / (self.sigma_data**2 + sigma**2).sqrt()
c_noise = sigma.log() / 4

# Key difference: concatenate scaled HR with raw LR
arg = torch.cat([c_in * x, img_lr], dim=1)
#     ↑ channels: [C_hr + C_lr, H, W]
#
# c_in scales ONLY the noisy HR image (normalizes it)
# img_lr is passed through UNSCALED (the LR image is clean, no noise)

F_x = self.model(arg, c_noise, ...)
D_x = c_skip * x + c_out * F_x
```

**Why concatenation and not cross-attention?**

```
CROSS-ATTENTION (used by Stable Diffusion for text):
  Text and images are DIFFERENT modalities (words vs pixels)
  They don't align spatially → need attention to find relationships
  
CHANNEL CONCATENATION (used by CorrDiff for LR images):
  LR and HR images are the SAME modality (both are weather maps)
  They align spatially (same lat/lon grid, just different resolution)
  → Simple concatenation works great and is much cheaper
```

**Analogy:** If you're solving a jigsaw puzzle:
- Cross-attention = having a verbal description of the picture ("there's a
  blue sky with clouds..."). You need to figure out which words correspond
  to which puzzle pieces. Complex!
- Concatenation = having a small, blurry photo of the completed puzzle taped
  to the box. You can directly compare each region of the puzzle to the
  corresponding region of the reference photo. Simple and effective!

## 7.2 The Two-Stage Architecture (Regression + Diffusion)

CorrDiff doesn't use a single model. It uses **two models in sequence**:

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  Stage 1: REGRESSION MODEL (deterministic)                   │
│                                                              │
│    Input:  LR weather data (ERA5, ~25km resolution)         │
│    Output: MEAN HR prediction (expected downscaling)        │
│                                                              │
│    This captures: large-scale patterns, average behavior     │
│    This misses:   fine-grained details, uncertainty          │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Stage 2: DIFFUSION MODEL (stochastic, EDM-based)           │
│                                                              │
│    Input:  LR data + RESIDUAL (HR truth - regression mean)  │
│    Output: Predicted residual (the missing fine details)     │
│                                                              │
│    This captures: turbulent structures, local variability,   │
│                   precipitation patterns, uncertainty        │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  FINAL OUTPUT = Regression prediction + Diffusion residual   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**Why two stages?**

```
SINGLE DIFFUSION MODEL:
  Must learn EVERYTHING — the large-scale average AND the fine details.
  The average pattern is "easy" (deterministic), but the diffusion model
  wastes capacity on it.

TWO-STAGE:
  The regression model handles the "easy" part (the mean).
  The diffusion model only needs to learn the "hard" part (the residuals).
  → More efficient, better quality, faster convergence.
```

**Analogy — Weather forecasting:** 🌤️
- Stage 1 is like the coarse forecast: "Tomorrow will be partly cloudy, 22°C"
  This is deterministic and usually quite accurate for the average.
- Stage 2 is like the uncertainty: "But there's a 40% chance of scattered
  showers in the northeast, with possible temperatures from 19-25°C"
  This is stochastic — different runs give different plausible scenarios.

## 7.3 Where σ Is Used in CorrDiff (Three Places)

During CorrDiff inference, σ appears in exactly the same three places as
in standard EDM:

```
PLACE 1: AS INPUT TO THE MODEL (telling it the noise level)
  ┌─────────────────────────────────────────────────────┐
  │ c_noise = log(σ) / 4                               │
  │ → sinusoidal embedding → FiLM conditioning          │
  │ → modulates every layer of the UNet                 │
  │                                                     │
  │ "Hey model, you're looking at noise level σ.        │
  │  Adjust your behavior accordingly."                 │
  └─────────────────────────────────────────────────────┘

PLACE 2: IN THE PRECONDITIONING (scaling inputs/outputs)
  ┌─────────────────────────────────────────────────────┐
  │ c_skip = σd² / (σ² + σd²)                          │
  │ c_out  = σ·σd / √(σ² + σd²)                       │
  │ c_in   = 1 / √(σd² + σ²)                          │
  │                                                     │
  │ "Adjust the microphone gain and amplifier settings  │
  │  for this particular noise level."                  │
  └─────────────────────────────────────────────────────┘

PLACE 3: IN THE SAMPLING STEP (computing the denoising direction)
  ┌─────────────────────────────────────────────────────┐
  │ d = (x - D(x; σ)) / σ                              │
  │ x_next = x + (σ_next - σ_cur) × d                  │
  │                                                     │
  │ "Use σ to normalize the denoising direction and     │
  │  determine the step size."                          │
  └─────────────────────────────────────────────────────┘
```

# Section 9: Summary and Cheat Sheet

## EDM in One Paragraph

EDM (Karras et al., 2022) is a **framework** that unifies all previous
diffusion models (DDPM, Score SDE, etc.) under a single equation:
`D(x;σ) = c_skip·x + c_out·F_θ(c_in·x; c_noise)`. It derives the
mathematically **optimal** values for the preconditioning coefficients
(c_skip, c_out, c_in, c_noise) so that the neural network F_θ always
sees unit-variance inputs and predicts unit-variance outputs, regardless
of the noise level σ. It samples σ from a log-normal distribution during
training, and uses a 2nd-order Heun sampler during inference with only
18 steps (vs DDPM's 1000). CorrDiff uses EDM because it's flexible,
stable, and state-of-the-art.

## The Five Key Ideas

```
1. UNIFICATION:    All diffusion models = same equation, different constants
2. PRECONDITIONING: Normalize inputs/outputs → stable training across all σ
3. LOG-NORMAL σ:   Smart sampling of noise levels → balanced training
4. HEUN SAMPLER:   2nd-order ODE solver → fewer steps, better quality
5. CONTINUOUS σ:   No discrete timesteps → flexible inference step count
```

## Quick Reference: The EDM Numbers

```
┌──────────────────────────────────────────────────────────┐
│  TRAINING                                                │
│    σ_data (sigma_data) = 0.5                            │
│    P_mean = -1.2    (log-normal mean)                   │
│    P_std  = 1.2     (log-normal std)                    │
│    → Most σ samples fall in [0.01, 10]                  │
│    → Peak around σ ≈ 0.3                                │
│                                                          │
│  INFERENCE (CorrDiff defaults)                           │
│    num_steps = 18                                       │
│    sigma_min = 0.002                                    │
│    sigma_max = 800                                      │
│    rho = 7           (schedule curvature)               │
│    S_churn = 0       (deterministic by default)         │
│    Sampler = Heun (2nd order)                           │
│    Total model calls ≈ 35                               │
│                                                          │
│  PRECONDITIONING FORMULAS                               │
│    c_skip  = σd² / (σ² + σd²)                          │
│    c_out   = σ · σd / √(σ² + σd²)                     │
│    c_in    = 1 / √(σd² + σ²)                          │
│    c_noise = log(σ) / 4                                 │
│    D(x;σ)  = c_skip·x + c_out·F_θ(c_in·x; c_noise)   │
└──────────────────────────────────────────────────────────┘
```
